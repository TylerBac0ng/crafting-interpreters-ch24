24.1 and 24.3 benchmark (bench/calls_bench.c): same machine, clang -O2,
median of 7 runs per program, load average about 2-4. Four builds:
  default    ip in a local variable, natives checked
  unchecked  ip in a local variable, -DUNCHECKED_NATIVES (book's natives)
  frameip    -DFRAME_IP (book's run()), natives checked
  both       -DFRAME_IP -DUNCHECKED_NATIVES (the book's chapter 24)

"unchecked" only changes callNative(), yet its loop with no calls is as slow
as frameip. That 13% is code layout, not the ip. So the builds were run again
with every basic block aligned (-mllvm -align-all-blocks=5), which takes most
of the layout luck away. Two rounds, both shown (ms):
                   default     unchecked    frameip      both
  fib(27)          53.0 53.4   52.1 52.2    58.3 54.3    56.8 54.4
  loop, no calls   970  972    992  991     1047 1046    1046 1047
  5M Lox calls     431  419    424  426     472  474     480  475
  5M native calls  385  384    386  386     427  436     431  439
  ns per native    18.7 18.6   16.8 17.4    19.3 20.9    20.1 21.5

With frameip, clang loads frame->ip from memory and stores it back for every
instruction it dispatches (movq 8(%r14) ... movq %rcx, 8(%r14)). With the
local, the ip stays in %r14. Aligned, that is 5-7% on the plain loop and about
10% on calls. The native checks cost 0-2 ns per call, less than the noise.
